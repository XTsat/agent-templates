# 模板工作流

> 本文件是根 [`AGENTS.md`](../AGENTS.md) 的细则页：**怎么用模板、怎么往新项目落**。
> 它不在自动注入范围内（候选文件名只有 `AGENTS.md`/`CLAUDE.md`/`AGENTS.local.md`/`CLAUDE.local.md`），需要时用 `read` 打开。
> 本文件上限 10 KB。

---

## 一、新增模板类型

1. 在 `templates/<类型>/` 下写一份入口 `AGENTS.md`（身份 + 硬规则 + 索引，≤ 16 KB）。
2. 篇幅大的细则放 `templates/<类型>/docs/`（**非候选文件名**），并在入口索引表点名。
3. 在同目录写 `check-anchors.txt`——派生项目的内容核验真源（格式见四「内容轴怎么判」）。**模板正文里「合并必留、重写必丢」的关键短语必须进清单**，否则该节被重写后无人察觉。
4. 在 `templates/<类型>/scaffold/` 下放骨架文件（后缀固定 `.template`）。
5. 在根 `README.md` 的「模板选择指南」表中登记一行。
6. 遵循 [`templates.md`](templates.md) 的章节要求与编写规范，推送前跑一次 `tools/check-derived.sh` 确认清单自检无「失配」告警。

---

## 二、「自动提取模板」时的行为准则

当用户要求「让 agent 从这个仓库学习 agent 并应用」时：

1. 在 `templates/` 下找到对应类型目录。判定依据：项目名含 `astrbot_plugin_` 前缀 → 用 `astrbot-plugin`；项目是 Next.js + TypeScript → 用 `nextjs-webapp`。
2. 完整阅读该目录的 `AGENTS.md`，再按它的索引表读需要的 `docs/` 细则。
3. 把 `scaffold/` 下的骨架文件复制到目标项目（去掉 `.template` 后缀）；`AGENTS.md` 一并复制，并原样保留头部的「模板版本」行——它是该项目日后与上游对齐版本的依据。**若该模板有 `docs/`，一并复制**（否则索引表里的指针会指向不存在的文件）。
4. 按 AGENTS.md 的规范初始化目标项目，而不是照搬本仓库已有仓库的个别写法。
5. 如果目标项目已有同名的 `AGENTS.md` / 配置文件，**先读再合并**，不得整文件覆盖丢失既有内容（参考多会话并行开发约束）。

## 三、往派生项目复制模板

当用户要求把这个仓库的模板用于新项目时，按三、的流程执行，另外注意：

- **`docs/` 要跟着走**：模板若有 `docs/`，必须一并复制到目标项目，否则入口 `AGENTS.md` 里的索引指针会指向不存在的文件。**正文引用了某个 `docs/` 文件却没有复制它，等于该节规则整节失效**——不是"少个附件"，`check` 会按「悬挂指针」报关键缺失。
- **模板版本行原样保留**：复制过去的 `AGENTS.md` 头部「模板版本」行不得改动，它是派生项目日后与上游对齐的依据。
- **合并而非覆盖**：目标项目已有同名 `AGENTS.md` / 配置文件时，先读再合并，禁止整文件覆盖。
- **章节编号不得重排**：派生项目可以增删章节、回填占位，但模板既有章节的编号与标题必须原样保留，新增章节一律**追加在末尾**。重排编号会让派生文件与上游失去可比性，日后只能整份重抄一遍——**重排即视为重写**（`check` 会以「疑似重写」提示）。

### 重写 vs 合并：判据是锚点，不是版本号

派生项目最常见的失效不是"忘了更新"，而是"重写了但头部版本号照抄"：文件被按项目重新组织，模板里的关键节（并行协议、更新流程、检查清单）在重排中被丢掉，而 `模板版本` 那一行原封不动——于是版本检查一看"落后 1 个 patch"，判定正常。

因此：

- **版本号是派生项目自己写的，不能作为内容齐全的证据**。合并完成后必须跑一次内容核验，见四。
- 「合并」的完成标准是**锚点齐全 + `docs/` 齐全**，不是"版本号改到最新"。

## 四、查派生项目落后情况

```bash
tools/check-derived.sh                     # 扫描默认根目录（本仓库的同级目录）
tools/check-derived.sh ~/workspace         # 指定根目录，可传多个
tools/check-derived.sh --format=markdown   # markdown 表格
tools/check-derived.sh --format=detail     # 逐项目列出缺失锚点、缺失 docs、结构提示
tools/check-derived.sh --quiet             # 只列非最新的
tools/check-derived.sh --stale=minor       # 只看跨 minor/major 的
tools/check-derived.sh --no-content        # 只看版本，跳过内容核验（旧行为）
GRACE_DAYS=0 tools/check-derived.sh        # 忽略传播期，看全部差距
tools/sync-check.sh <派生项目路径>          # 单个项目一条命令拿差异（= --project）
```

输出：派生项目 / 模板 / 本地 / 上游 / 差几版 / **版本** / **内容**。

### 两个独立的判定轴

| 轴 | 依据 | 含义 |
|---|---|---|
| **版本** | 头部「模板版本」行 vs 上游当前版本 | 只说明"声明的是哪个版本"，不证明正文在 |
| **内容** | `templates/<模板>/check-anchors.txt` 的锚点清单 | 关键节是否**真的存在**，`docs/` 是否有悬挂指针 |

两轴必须分开看，因为**版本号写对不等于内容齐全**（见三「重写 vs 合并」）。

### 内容轴怎么判

- **锚点清单**放在 `templates/<模板>/check-anchors.txt`，不写死在脚本里、也不进 `AGENTS.md`（不占 16 KB 正文预算）。改模板正文时**同步维护该清单**；清单里写了的短语在模板正文找不到时，脚本会往 stderr 打「锚点清单失配」——清单不能变成第二份真源。
- 清单只取**合并时必然保留、被重写时必然丢失**的稳定短语（如 `多会话并行`、`禁止整文件覆盖`、`更新 AGENTS`），**不取章节编号或完整标题**——派生项目合法地会增删章节、回填内容。
- `docs` 类锚点只在**正文真的引用了该路径**时才要求文件存在：正文没引用 = 老版本正文内联，正常；正文引用了但文件不在 = **悬挂指针**，规则静默失效，判关键缺失。
- 关键锚点（`blocker`）缺失**不受传播期豁免**，退出码直接非零；`warn` 级只提示，不影响退出码。
- 「结构」一栏是模板章节标题在派生文件里的留存情况，**仅作诊断提示**，永不参与退出码——章节增删是合法的，只有连锚点都缺时它才有参考价值。


### 判定为什么分级

**模板发版很频繁**（实测 `astrbot-plugin` 19 天发了 11 个版本，平均不到 2 天一个）。如果一升版就把所有派生项目判为"落后"，告警会永远满屏——这不是故障，是常态。所以按落差分级：

| 状态 | 含义 | 要不要处理 |
|---|---|---|
| `✅ 最新` | 与上游同版本 | 否（但**仍需看内容栏**） |
| `○ 落后 patch` | 只差几个 patch | **否**，下次顺手带上即可 |
| `⚠️ 跨 minor` | 跨了 minor 档（规则或结构有变） | 值得安排一次合并 |
| `❗跨 major` | 跨了 major 档（必须迁移） | 必须处理 |
| `◻ 早于版本行` | 派生早于 2026-10-21（版本行引入日），没有版本行 | 合并一次上游即补齐，不算漏写 |
| `❓ 领先上游` | 本地版本比上游新 | 检查是否本地改错了版本行 |

内容栏另有一套取值，与上面这栏互不影响：

| 内容 | 含义 | 要不要处理 |
|---|---|---|
| `✅ 齐全` | 关键锚点都在，无悬挂 `docs` 指针 | 否 |
| `○ 有提示` | 只缺 `warn` 级锚点（如来源行、版本行） | 计入下次合并，不告警 |
| `❗内容缺失` | 缺 `blocker` 级锚点，或 `docs` 有悬挂指针 | **必须补**，与版本栏无关 |

### 传播期（为什么刚发版时不告警）

当前上游版本段发布不足 `GRACE_DAYS`（默认 7）天时，所有**落后项**不计为异常，并打印一行提示。

理由就是你想到的那个：**刚升版，其他项目还没来得及跟**。没有传播期，每次发版都会立刻满屏告警，告警就失去意义。想看真实差距用 `GRACE_DAYS=0`。

**传播期只豁免版本轴，不豁免内容轴**：刚发版不会让派生项目原本就缺的章节凭空长回来。缺的内容与哪次发版无关，任何时期都算问题。

### 退出码

- `2` —— 存在 `❗内容缺失`（关键锚点缺失 / 悬挂指针），**任何时期都算，不受传播期与 `--stale` 过滤影响**
- `1` —— 传播期外且存在 `⚠️ 跨 minor` 或 `❗跨 major`
- `0` —— 无问题。`○ 落后 patch` **不算失败**，`○ 有提示` 也不算

可以直接挂推送前检查。加了内容轴后，第一次跑可能会因为历史遗留突然非零——这正是它要报的东西，按内容栏逐条补即可；确实要临时放行用 `--no-content`。


### 不要手工维护一览表

脚本每次实时扫描磁盘，不缓存、不落盘快照——所以不存在"汇总页过期"问题。**手工维护的派生项目版本汇总表必然双写不一致**，本仓库禁止这种表（见根 `AGENTS.md` §4.2）。

需要给人类看的一览表时，用生成的方式，且带时间戳：

```bash
tools/check-derived.sh --format=markdown > /tmp/derived-status.md
```

### 只统计真正的派生项目

`AGENTS.md` 里必须出现 `agent-templates` 或 `templates/<模板名>` 才算派生。外部项目自带的 `AGENTS.md`（如 AstrBot 上游、Archify）会被自动跳过。
