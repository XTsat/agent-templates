# 模板工作流

> 本文件是根 [`AGENTS.md`](../AGENTS.md) 的细则页：**怎么用模板、怎么往新项目落**。
> 它不在自动注入范围内（候选文件名只有 `AGENTS.md`/`CLAUDE.md`/`AGENTS.local.md`/`CLAUDE.local.md`），需要时用 `read` 打开。
> 本文件上限 10 KB。

---

## 一、新增模板类型

1. 在 `templates/<类型>/` 下写一份入口 `AGENTS.md`（身份 + 硬规则 + 索引，≤ 16 KB）。
2. 篇幅大的细则放 `templates/<类型>/docs/`（**非候选文件名**），并在入口索引表点名。
3. 在 `templates/<类型>/scaffold/` 下放骨架文件（后缀固定 `.template`）。
4. 在根 `README.md` 的「模板选择指南」表中登记一行。
5. 遵循 [`templates.md`](templates.md) 的章节要求与编写规范。

---

## 二、「自动提取模板」时的行为准则

当用户要求「让 agent 从这个仓库学习 agent 并应用」时：

1. 在 `templates/` 下找到对应类型目录。判定依据：项目名含 `astrbot_plugin_` 前缀 → 用 `astrbot-plugin`；项目是 Next.js + TypeScript → 用 `nextjs-webapp`。
2. 完整阅读该目录的 `AGENTS.md`，再按它的索引表读需要的 `docs/` 细则。
3. 把 `scaffold/` 下的骨架文件复制到目标项目（去掉 `.template` 后缀）；`AGENTS.md` 一并复制，并原样保留头部的「模板版本」行——它是该项目日后与上游对齐版本的依据。**若该模板有 `docs/`，一并复制**（否则索引表里的指针会指向不存在的文件）。
4. 按 AGENTS.md 的规范初始化目标项目，而不是照搬本仓库已有仓库的个别写法。
5. 如果目标项目已有同名的 `AGENTS.md` / 配置文件，**先读再合并**，不得整文件覆盖丢失既有内容（参考多会话并行开发约束）。

## 三、往派生项目复制模板

当用户要求把这个仓库的模板用于新项目时，按三、的流程执行，另外注意：

- **`docs/` 要跟着走**：模板若有 `docs/`，必须一并复制到目标项目，否则入口 `AGENTS.md` 里的索引指针会指向不存在的文件。
- **模板版本行原样保留**：复制过去的 `AGENTS.md` 头部「模板版本」行不得改动，它是派生项目日后与上游对齐的依据。
- **合并而非覆盖**：目标项目已有同名 `AGENTS.md` / 配置文件时，先读再合并，禁止整文件覆盖。

## 四、查派生项目落后情况

```bash
tools/check-derived.sh                     # 扫描默认根目录（本仓库的同级目录）
tools/check-derived.sh ~/workspace         # 指定根目录，可传多个
tools/check-derived.sh --format=markdown   # markdown 表格
tools/check-derived.sh --quiet             # 只列非最新的
tools/check-derived.sh --stale=minor       # 只看跨 minor/major 的
GRACE_DAYS=0 tools/check-derived.sh        # 忽略传播期，看全部差距
```

输出：派生项目 / 模板 / 本地 / 上游 / 差几版 / 状态。

### 判定为什么分级

**模板发版很频繁**（实测 `astrbot-plugin` 19 天发了 11 个版本，平均不到 2 天一个）。如果一升版就把所有派生项目判为"落后"，告警会永远满屏——这不是故障，是常态。所以按落差分级：

| 状态 | 含义 | 要不要处理 |
|---|---|---|
| `✅ 最新` | 与上游同版本 | 否 |
| `○ 落后 patch` | 只差几个 patch | **否**，下次顺手带上即可 |
| `⚠️ 跨 minor` | 跨了 minor 档（规则或结构有变） | 值得安排一次合并 |
| `❗跨 major` | 跨了 major 档（必须迁移） | 必须处理 |
| `◻ 早于版本行` | 派生早于 2026-10-21（版本行引入日），没有版本行 | 合并一次上游即补齐，不算漏写 |
| `❓ 领先上游` | 本地版本比上游新 | 检查是否本地改错了版本行 |

### 传播期（为什么刚发版时不告警）

当前上游版本段发布不足 `GRACE_DAYS`（默认 7）天时，所有落后项**不计为异常**，退出码恒为 0，并打印一行提示。

理由就是你想到的那个：**刚升版，其他项目还没来得及跟**。没有传播期，每次发版都会立刻满屏告警，告警就失去意义。想看真实差距用 `GRACE_DAYS=0`。

### 退出码

- 传播期内：恒为 `0`
- 传播期外：只有存在 `⚠️ 跨 minor` 或 `❗跨 major` 时返回非零；`○ 落后 patch` **不算失败**

可以直接挂推送前检查。

### 不要手工维护一览表

脚本每次实时扫描磁盘，不缓存、不落盘快照——所以不存在"汇总页过期"问题。**手工维护的派生项目版本汇总表必然双写不一致**，本仓库禁止这种表（见根 `AGENTS.md` §4.2）。

需要给人类看的一览表时，用生成的方式，且带时间戳：

```bash
tools/check-derived.sh --format=markdown > /tmp/derived-status.md
```

### 只统计真正的派生项目

`AGENTS.md` 里必须出现 `agent-templates` 或 `templates/<模板名>` 才算派生。外部项目自带的 `AGENTS.md`（如 AstrBot 上游、Archify）会被自动跳过。
