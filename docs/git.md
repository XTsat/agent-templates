# 提交信息细则

> 本文件是根 [`AGENTS.md`](../AGENTS.md) 的细则页：**提交信息每个字段该写什么**。
> 它不在自动注入范围内（候选文件名只有 `AGENTS.md`/`CLAUDE.md`/`AGENTS.local.md`/`CLAUDE.local.md`），需要时用 `read` 打开。
> 本文件上限 10 KB——`read` 工具单次返回上限 50 KB，超过就要分次读，模型会放弃。

---

## 格式

Conventional Commits：`<type>(<scope>): <subject>` + 可选正文 + 可选 footer。

**格式之外还有内容标准**——只写「遵循 Conventional Commits」等于没写，agent 仍会随手造空话标题。下面六项缺一不可。

---

## 一、type：按「读者得到什么」选，不按改了哪些文件

| type | 用在哪 | 不要用在哪 |
|---|---|---|
| `feat` | 新增模板、骨架文件、可感知能力 | 只改既有规范措辞 |
| `fix` | 修正错误的规范、坏示例、失效命令 | 「顺手改得更顺」的重写 |
| `docs` | 纯规范文本与说明（**改模板正文一律用它**） | 同时动了骨架文件时 |
| `refactor` | 不改变任何约定的结构调整（章节重排、链接整理） | 措辞变了但声称没变 |
| `perf` | 可测量的性能改善 | 「感觉更快了」 |
| `test` / `build` / `ci` / `chore` / `style` / `revert` | 按字面含义 | 拿 `chore` 当「杂七杂八」的垃圾桶 |

判定动作：先问「使用者读完这条，能决定要不要更新吗」，能 → `feat`/`fix`；不能但确实改了规范 → `docs`。

---

## 二、scope：一个词，取模块名

- 合法取值：`templates`（跨模板）、`astrbot-plugin` / `nextjs-webapp` / `generic`（单模板）、`skills`、`docs`、`tools`、`readme`、`changelog`。
- 无明确归属就**省略**（`docs: 修正错别字` 比 `docs(misc): ...` 好）。
- **禁止** `misc` / `update` / `all`；**禁止**用文件名当 scope（`docs(AGENTS.md)` ❌）。

---

## 三、subject：一句话说清做了什么

- 中文动宾短句，以 `新增` / `修复` / `调整` / `移除` / `重命名` / `改写` 开头。
- **≤ 28 汉字**，整行（含 type/scope）**≤ 72 字符**。
- 只讲一件事；不加句号；不写版本号与日期（版本号在发版提交里由 CHANGELOG 体现）。
- **禁用空话**：「优化」「完善」「修复若干问题」「更新文档」「调整结构」——这些换个仓库也成立，等于没说。

---

## 四、正文：可选，不强制

**只在改动本身从 diff 看不出来时才写**，写这三类：

1. 取舍理由（为什么选 A 不选 B）；
2. 需要使用者**动手**的迁移动作；
3. 破坏性变更的具体影响。

格式：每行 `- ` 开头，**≤ 5 条**。

**不要写**：验证过程、影响面盘点（影响哪些派生项目/用户）、版本号递增流水、后续计划、过程与情绪。没有值得写的就**留空**，不为凑格式硬写。

---

## 五、footer

- `BREAKING CHANGE:` —— 派生项目必须动手迁移时，写清**迁移动作**（不是「有破坏性变更」）。
- `Refs: #123` —— issue / PR 编号。
- `Co-authored-by:` —— 协作者。
- issue 编号**不进 subject**（`fix: 修复 #123 的崩溃` ❌ → `fix: 修复空配置时的崩溃` + `Refs: #123` ✅）。

---

## 六、粒度：一个提交一件事

- 一个提交只做一件事；**文档与代码同提交**（不单独拆「补文档」提交）。
- 同一改动的三份模板 + 根 README + 版本号递增放**同一提交**，不拆成「改模板」「涨版本号」两次。
- 不提交半成品与中间态。

---

## 正反例

```
✅ docs(templates): 提交规范补内容标准
✅ feat(astrbot-plugin): 新增 views 骨架
✅ docs(generic): 版本号改为只在发版时递增
❌ docs: 更新文档                                          # 空话，看不出改了什么
❌ docs(templates): 优化提交规范并调整 README 表格、顺便涨版本号   # 三件事 + 超长
❌ fix: 修复 #123 的崩溃                                    # issue 编号进了 subject
```

---

## 自查

`git log --oneline -10` —— **不看 diff 也能读懂每个提交做了什么**，且相邻提交没有重复描述同一件事。读不懂就是写坏了，重写标题。
